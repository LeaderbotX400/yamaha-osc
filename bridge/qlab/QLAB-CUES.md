# QLab → TF bridge: template cues to copy

This is the copy‑paste reference for building QLab OSC cues that drive the `tf-bridge.py`
running on the theatre MacBook. Every cue below is an **OSC cue** whose destination is the
already‑configured **`TF3`** network patch (`127.0.0.1:8000`, UDP) — the port the bridge listens on.

There are two ready-made starting points on the Desktop:
- **`TF Bridge Template.qlab5`** — has a **`TF BRIDGE TEMPLATES`** group pre-filled with one ready
  cue per function below (generated by `generate.applescript`). Copy a cue, change the channel
  number/value, done.
- **`Musical Show & Lights Template.qlab5`** — the original base, with the `/tf/*` show cues.

`TF3` is now the **first** network patch (Settings → Network → OSC), pointing at `127.0.0.1:8000`
(the bridge). The old loopback "Patch 1" was removed, so **new Network cues default to `TF3`** — no
per-cue patch step needed. (If you ever add a cue that isn't on `TF3`, select it and pick `TF3` as
its Destination.)

Workflow for a new cue by hand: **new Network cue → paste a message string below → set name/number.**

> Bridge and QLab run on the **same Mac**, so the destination is loopback (`127.0.0.1:8000`),
> not the console's IP. The bridge is what talks to the console at `192.168.50.2:49280`.

## Making one cue by hand

1. Select the palette **OSC** cue and press **⌘D** to duplicate it (or **Cues ▸ OSC** for a new one).
2. In the **Settings** (inspector) tab, set **Destination** to the **`TF3`** patch.
3. Set **Message type** to **OSC message**.
4. In the message field, type one of the strings from the tables below.
5. Give the cue a **Name** and **Number** (the tables suggest both).

**Argument tips (how QLab parses the message text):**
- Numbers are sent as numbers: `-6.0` → float, `1` → int. The bridge accepts either.
- A text value that contains a space **must be quoted**: `/ch/1/name "Lead Vox"` sends one string;
  without quotes QLab sends two (`Lead`, `Vox`).
- `inf` / `-inf` for a fader go to −∞; anything ≤ about −327 dB is treated as −∞ too.
- Channel/bus numbers in the address are **1‑based**, exactly like the console surface
  (channel 1 on the desk = `/ch/1/...`).

## Core input‑channel cues (new grammar)

| Suggested name | # | OSC message | Effect |
|---|---|---|---|
| CH 1 · fader → 0 dB | 101 | `/ch/1/fader 0.0` | Set input 1 fader to 0 dB |
| CH 1 · fader → −∞ | 102 | `/ch/1/fader -inf` | Kill input 1 fader |
| CH 1 · fade → −30 / 2 s | 103 | `/ch/1/fade -30.0 2000 cosine` | Ramp input 1 to −30 dB over 2 s (cosine) |
| CH 1 · fade up → 0 / 1.5 s | 104 | `/ch/1/fade 0.0 1500 cosine` | Ramp input 1 up to 0 dB over 1.5 s |
| CH 1 · MUTE | 105 | `/ch/1/mute 1` | Mute input 1 (fader off) |
| CH 1 · UNMUTE | 106 | `/ch/1/mute 0` | Unmute input 1 |
| CH 1 · ON | 107 | `/ch/1/on 1` | Channel on |
| CH 1 · name | 108 | `/ch/1/name "Lead Vox"` | Set the channel name |
| CH 1 · colour | 109 | `/ch/1/color Blue` | Colour ∈ Purple/Pink/Red/Orange/Yellow/Blue/SkyBlue/Green |
| CH 1–8 · MUTE (range) | 110 | `/ch/1-8/mute 1` | Mute inputs 1–8 in one cue |

Curves for `fade`: `linear`, `cosine` (default if omitted), `exp`. A later `fade`/`fader` on the
same channel cancels an in‑progress fade.

## Sends (input → mix bus)

| Suggested name | # | OSC message | Effect |
|---|---|---|---|
| CH 1 → Mix 3 · level | 121 | `/ch/1/send/mix/3/fader -6.0` | Input 1 send to mix 3 at −6 dB |
| CH 1 → Mix 3 · on | 122 | `/ch/1/send/mix/3/on 1` | Turn that send on (0 = off) |
| CH 1 → Mix 3 · fade | 123 | `/ch/1/send/mix/3/fade -20.0 1500` | Ramp that send level |

## Output strips (mix / matrix / stereo / mono)

| Suggested name | # | OSC message | Effect |
|---|---|---|---|
| MIX 3 · fader | 141 | `/mix/3/fader 0.0` | Mix bus 3 master fader |
| MATRIX 1 · fader | 142 | `/mtrx/1/fader 0.0` | Matrix 1 fader |
| STEREO · fader | 143 | `/st/1/fader 0.0` | Stereo (main L/R) master |
| MONO · fader | 144 | `/mono/1/fader 0.0` | Mono master |
| STIN 1 · on | 145 | `/stin/1/on 1` | Stereo input 1 on |
| FXRTN 1 · fader | 146 | `/fxrtn/1/fader 0.0` | FX return 1 fader |

## DCAs

| Suggested name | # | OSC message | Effect |
|---|---|---|---|
| DCA 1 · fader | 161 | `/dca/1/fader 0.0` | DCA 1 fader |
| DCA 1 · MUTE | 162 | `/dca/1/mute 1` | Mute DCA 1 (writes both DCA + DcaCh) |
| DCA 1 · ON | 163 | `/dca/1/on 1` | DCA 1 on |

## Mute groups & scenes

| Suggested name | # | OSC message | Effect |
|---|---|---|---|
| MUTE GROUP 1 · engage | 181 | `/mutegroup/1 1` | Engage mute group 1 (0 = release) |
| SCENE · recall A12 | 182 | `/scene/recall a 12` | Recall scene 12, bank A. **Mutes re‑assert on top.** |
| SCENE · recall B03 | 183 | `/scene/recall b 3` | Recall scene 3, bank B |

`scene/recall` is **stateful**: after the scene loads, any mutes you set through the bridge are
re‑applied on top of it (so a muted channel stays muted across a scene change).

## Legacy `/tf/*` cues (unchanged — existing shows keep working)

These are the addresses the old Python bridge used. They still work, so cues built before this
migration need no changes. Prefer the new grammar above for anything new.

| Suggested name | # | OSC message | Effect |
|---|---|---|---|
| TF · mute 1 3 5 | 201 | `/tf/mute 1 3 5` | Mute inputs 1, 3, 5 (token grammar) |
| TF · unmute 1 3 5 | 202 | `/tf/unmute 1 3 5` | Unmute the same |
| TF · mute aux 9/10 | 203 | `/tf/mute aux 9` | Mute aux (stereo‑pair aware): `aux`, `matrix`, `dca`, `fx1`, `st1`, `master`, `sub` |
| TF · scene A12 | 204 | `/tf/scene A12` | Recall scene A12 (mutes re‑assert) |

Full address grammar (both schemes) lives in `../OSC-REFERENCE.md`.

## Notes on the destination patch

If the `TF3` patch is ever missing from a workspace, recreate it under
**Settings → Network → OSC**: a UDP patch to **`127.0.0.1`** port **`8000`**, and keep it **first**
in the list so new cues default to it. To retarget the whole show at a different bridge, you only
change this one patch — no cue edits.

## Regenerating the template group

`generate.applescript` (next to this file) rebuilds the `TF BRIDGE TEMPLATES` group from scratch in
the frontmost QLab workspace: `osascript generate.applescript`. Edit the `cueData` list to change
which cues it produces. It documents the QLab-5.6.3 scripting quirks worth knowing if you extend it.
